# ADR（設計判断の記録）

技術や設計を選ぶたびに1ファイル書く。テーマ "Own the Why, Build with Intent." に沿って、AI の提案を鵜呑みにせず、**比べた案・選んだ理由・捨てた理由**を自分たちの言葉で残す。提出ドキュメントの「選定理由・メリット/デメリット」欄は、ここから写す。

## 一覧

| 番号 | 題名 | 状態 |
|---|---|---|
| [0001](0001-ai-role.md) | AI に判定させず、人の判断材料を揃える | 決定 |
| [0002](0002-gemini-via-vertex-ai.md) | Gemini は Vertex AI 経由で呼ぶ | 決定 |
| [0003](0003-runtime-and-stack.md) | 実行基盤と技術構成 | 決定（11/7） |

| [0005](0005-dev-and-submission-repos.md) | 開発用と提出用のリポジトリを分ける | 決定 |
| [0006](0006-theme-nursing-record.md) | 看護記録の二度手間を減らすアプリを作る | 決定 |

状態は「提案中」「決定待ち」「決定」「取り下げ」のどれか（「決定待ち」は、決めかけた案が使えなくなり選び直しているもの）。提案中のものは、チームで話して決めたら「決定」にし、決めた日と決めた人を書く。

## 書き方（コピーして使う）

```markdown
# NNNN. 題名

- 状態：提案中 / 決定 / 取り下げ
- 日付：YYYY-MM-DD
- 決めた人：

## 背景
何を決める必要があるか。制約（期間・費用・ルール）。

## 比べた案
| 案 | 利点 | 欠点 |
|---|---|---|

## 決めたこと
## 選んだ理由
## 捨てた案と、捨てた理由
## この決定で困ること・後で見直す条件
## AI の使い方
この判断で AI に何を聞き、何を採り、何を採らなかったか。
```
