# 0005. 開発用と提出用のリポジトリを分ける

- 状態：決定
- 日付：2026-11-05
- 決めた人：Cさん

## 背景

- 運営が用意した提出用リポジトリ（`Devfest-Hackathon-2026/df-2026-t172`）は**公開**で、開催中も他の参加者から見える
- 提出用リポジトリでは GitHub Actions と GitHub Pages が使えない
- 締切（11/10 19:00）を過ぎると読み取り専用になる。審査は提出用リポジトリの中身だけで行われる

## 比べた案

| 案 | 利点 | 欠点 |
|---|---|---|
| A. 提出用リポジトリで直接開発する | 移す手間がない | 作りかけのものや試行錯誤が全部公開される。CI が使えない。秘密情報を誤ってコミットすると即公開 |
| B. 非公開の開発用リポジトリで開発し、最終版だけ移す | 開発中は非公開。CI も使える | 移す作業が要る。移し忘れたものは審査されない |

## 決めたこと

B を採る。

- 開発は、チームの非公開の開発用リポジトリで行う
- 締切の前日（11/9）までに一度、提出用リポジトリへ移す練習をする
- 移すときは履歴を持ち込まず、最終版のファイルだけをコピーしてコミットする
- 移したあと、提出用リポジトリの中身で起動できるか確かめる

## 選んだ理由

- 公開リポジトリで秘密情報を漏らす危険を減らす（審査の「安全性」）
- 運営も別リポジトリでの開発を勧めている

## この決定で困ること・後で見直す条件

- 移し忘れ。→ 移す対象の一覧を `docs/submission/README.md` に置き、締切前に照らし合わせる
