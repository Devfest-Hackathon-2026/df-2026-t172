## プロダクト（NurseNote）

元にした資料（2026-11-16 時点）：`docs/submission/submission-readme.md`、`docs/adr/0001-ai-role.md`、`docs/adr/0006-theme-nursing-record.md`、`docs/research/hearing.md`

### 誰の、どんな困りごとか

病棟の看護師。ヒアリング（看護師1名）で聞いた事実：

- 聞いたこととバイタルを**一度メモしてから、後でパソコンに入力し直している**（二度手間）
- その場で残せないと、患者の発言を後で思い出せない
- 患者からの依頼は自分のメモ・張り紙・申し送りで扱い、**「後でします」と言って忘れることが多々ある**
- 記録は SOAP で書いている。術後はモニターで値を見て、熱だけ測ることがある
- 病院では録音が個人情報の点で難しいかもしれない（正式な禁止かは未確認）。チームは**録音できる前提**で作ると決めた（病院の許可と本人の同意が前提）

看護師1名の経験なので、現場全体に一般化しない。資料では「聞いた事実」と「チームの解釈」を分けて書く。

### 何をするアプリか

1. 看護師が名簿から患者を選び、同意を確かめてから録音する（またはテキストを入れる）
2. Speech-to-Text が発言の列（番号・話者・時刻）を作る
3. Gemini が、SOAP の S（患者の訴え）・O（観察・測定）の下書き、バイタル、患者の依頼を、**根拠の発言番号つき**で返す
4. コードの照合と Gemini の二段目の確認で、**AI が根拠なしに補った部分を目立たせる**
5. 看護師が1文ずつ確かめて確定する。カルテに貼る文を出し、依頼は緊急度3段のタスクになる

### 一番大事な考え方（テーマ "Own the Why, Build with Intent."）

- **AI に判定させない**。AI は材料をそろえ、判断と確定は看護師がする
- AI が書くのは S と O だけ。A（アセスメント）と P（計画）は看護師が書く
- 診断・医療的な判断・依頼の優先順位・薬の名前と量は、AI に書かせない
- AI の答えを AI だけで確かめない。値・数・話者・薬の語・患者の取り違えは**コードで**照合する
- 持たないデータは漏れない：音声と会話の全文は保存しない。記録とタスクも翌日0時以降に消す

この考え方を弱める変更（AI に優先度を決めさせる、A・P を AI に書かせる、照合を AI 任せにする、など）は、提案するときに必ずその旨と理由を書き、人に決めてもらう。

### 既存製品との違い（調べた範囲で）

- 根拠のない部分を目立たせる、書くべき項目の抜けを教える、依頼をタスクにする
- 国内の看護記録の AI は訪問看護向けが中心で、病棟のベッドサイド向けは少ない
- 動画・資料では他社の製品名を出さない（H-01）

## 技術構成

元にした資料（2026-11-16 時点）：`docs/adr/0002`〜`0004`、`docs/submission/architecture.md`、`backend/README.md`

### 使っているもの

| 部分 | 使っているもの | 決めた理由 |
|---|---|---|
| 実行 | Cloud Run（`asia-northeast1`、**最大1インスタンス**）。FastAPI が API と画面を1つのコンテナで配信（直下の `Dockerfile`） | ADR-0003。1日の回数上限をメモリで数えるため1台に固定 |
| バックエンド | Python 3.11 以上・FastAPI・pydantic | ADR-0003 |
| 画面 | HTML・CSS・素の JavaScript（ES モジュール、ビルドなし）。単一ページで画面を切り替える | Bさんが慣れた技術 |
| 下書きと二段目の確認 | Vertex AI の Gemini。モデル `gemini-3.5-flash`、場所 `global`、思考 `thinking_level=MINIMAL`、構造化出力 | ADR-0004（gemini-2.5-flash は廃止済み。東京は従量課金で呼べないので `global`。P-05 の例外） |
| 文字起こし | Speech-to-Text V2、`chirp_3`、場所 `us`、話者分離・時刻つき。1回60秒までなので 55秒ずつ5秒重ねて区切る。音声は ffmpeg で FLAC に変換 | 東京では日本語の chirp_3 が使えなかった（P-05 の例外） |
| 保存 | Firestore（`(default)`、`asia-northeast1`、ネイティブ）。`records`・`tasks` の `expires_at` に TTL。画面からの読み書きは `firestore.rules` で全部拒否 | ADR-0003、SEC-02 |
| 秘密情報 | Secret Manager（`asia-northeast1`）。合言葉 `PASSCODE` と署名の鍵 `ENTAIL_SEAL_KEY`。**バージョンは番号で固定**（`latest` にしない） | SEC-03 |
| 認証 | GCP へは Cloud Run のサービスアカウント `cloud-run-vertex-sa`。**API キー・鍵ファイルは使わない**。利用者は合言葉（`X-Passcode`）だけで、ログインはない | ADR-0002、`docs/design/auth.md` |
| ログ | 標準出力に JSON 1行（Cloud Logging）。会話の文・患者名・例外の本文は出さない | P-04 |

GCP プロジェクトは `df-2026-t172`。動いているサービスは `nursing-draft`（mock）と `nursing-draft-live`（live）。

### モード

- `MODE=mock`：Gemini・Speech-to-Text・Firestore を**一切呼ばない**。利用シーン5場面の見本（`backend/mock/`）で動く。開発と画面の確認は、まずこちら
- `MODE=live`：本物を呼ぶ。**お金がかかるので、Cさんの承認なしに使わない**（[conventions.md](conventions.md) の「お金がかかる呼び出しと GCP の設定変更」）
- すべての応答に `mode` を入れ、画面の隅に常に出す（C-07。モックを本物に見せるとデモの偽装になる）

### 技術を変えるとき

- モデル・リージョン・保存先・認証の方式を変える提案は、**先に ADR を書いて人に決めてもらう**。コードを先に書き換えない
- モデルを変えるときに確かめること：構造化出力に対応しているか、廃止日、使う場所で従量課金で呼べるか、思考の止め方、1回の費用（公式ページで確かめる。記憶で書かない）
- 新しいライブラリを足すときは、ライセンスを確かめて `docs/submission/license-sheet.md` に1行足す
