# 決まりの一覧（運用ルール）

アプリが守る決まりを、分野ごとに番号を付けて1か所にまとめる。**どこで守らせるか**を必ず決める。

| 守らせる場所 | 意味 |
|---|---|
| **B**（バックエンド） | コードで強制する。破られたら API がエラーを返す。テストで確かめる |
| **F**（画面） | 見せ方・お知らせ。**F だけで守らせる決まりは作らない**（画面の作りに漏れがあっても安全が崩れないように、大事なものは必ず B でも止める） |
| **設定** | GCP の設定（Cloud Run、Firestore、予算）。提出前に設定し、提出後は変えられない |
| **人** | 使う人・チームが守る。説明資料に書く |

- 【未決】の所は、案を書いてある。チームで決めたら【決定】に書き換える
- バックエンドのテストは、ここの番号（例 `A-05`）をテスト名に入れる
- 説明ドキュメントの「安全性」の欄は、この表から写す

## 1. 患者の安全（取り違え・誤った値）

| 番号 | 決まり | なぜ | 場所 | 確かめ方 |
|---|---|---|---|---|
| S-01 | 患者は名簿から選ぶ。会話で言った部屋番号・名前は、選んだ患者との照合にだけ使う | 声だけで患者を決めると、漢字の揺れ・同姓・多床室で取り違える | B・F | 照合のテスト |
| S-08 | 【決定】名簿は**病棟の患者一覧**（架空、起動時に入れる。部屋番号の順）。管理の画面は作らない。**ログインなしで、依頼（タスク）の担当だけを割り振る**：患者には基本の受け持ち（架空の看護師、`backend/seed/` から入れる）があり、タスクは作ったときにその受け持ちを担当にする。看護師は「担当に回す」「自分で引き取る」で担当を変えられ、「自分の担当だけ」に絞って見られる。患者の受け持ちもその日に変えられ（`PATCH /api/patients/{id}`）、変えると、担当を人が変えていない（`rule`）未完了のタスクも新しい受け持ちに移る（看護師が回した・引き取ったタスクと済みのタスクは動かさない）。画面で変えた受け持ちは、再起動で seed に戻さない。担当・受け持ちにできるのは看護師の一覧（`GET /api/nurses`）にいる人だけ（ほかは `422`）。ログインがないので、**誰が変えたか・確定したかは自己申告で残す**：画面で選んだ「自分」を `reported_by` で送り、タスク・名簿・記録に `*_reported_by` として残し、変更は操作記録にも出す。本人の確かめはなく、「誰がやったと言っているか」までしか言えない（証拠にはならない）。「自分」を選んでいなければ空（`null`）。合言葉を知っていれば誰でも誰の担当でも変えられる。本番では病院の認証と電子カルテの受け持ち表に連携する（範囲外。資料に書く、[auth.md](auth.md)） | 現場の声：「基本の受け持ちは決まっているが、その日の担当は変わることもある。担当外の患者さんからの依頼は、状況によって担当に頼むか、自分で対応している」。その日の受け持ちの入れ替えにも合わせる。患者の情報（名簿）はアプリで持ち続けず、本番では電子カルテから読む | B・F | `test_S08_patients_are_ward_list_by_room`、`tests/test_rules_assignment.py`・`tests/test_rules_assignee_change.py`（`test_S08_*`）。起動時に名簿が入ったかは設定（人） |
| S-02 | 照合の結果は3段。緑（一致）、黄（照合できず＝言っていない、または名簿にない部屋番号が聞こえた＝聞き違いの可能性）、赤（食い違い＝名簿のほかの患者の部屋番号・名簿の別の患者の名前） | 色と止め方を一律にする。聞き違いで赤が続くと、看護師が中身を見ずに確認を押す癖がつく（11/8 の技術検証で「310号室」が「315号室」と聞こえた） | B | 照合のテスト（`test_S02_unlisted_room_number_is_yellow` ほか） |
| S-03 | 黄・赤のときは、看護師が「この患者で正しい」と確認するまで確定できない（`patient_confirmed`） | 取り違えを確定させない | B（`409`）・F | 確定の API のテスト |
| S-04 | 【決定】赤のとき、理由の入力は要らない。確認だけで確定でき、記録に「照合で食い違いあり→看護師が確認」と残す | 入力が重いと使われない。ただし後から追えるようにする | B | `test_S04_red_confirmed_without_reason_is_noted` |
| S-05 | 録音中と確認画面に、選んだ患者の名前を大きく出す | 名簿の隣の行を押した誤りに、その場で気づく | F | 画面で確認 |
| S-06 | カルテ用の文の先頭に、患者の氏名・部屋・日時を必ず入れる | 貼り先のカルテを間違えても気づける | B | 確定の API のテスト |
| S-07 | バイタルの値が会話の値と違う、最新の値でない、同じ項目が2つ、のどれかなら止める。会話に値が複数あれば必ず注意を出し、看護師に選ばせる | 聞き違い・言い直しの古い値を記録しない | B | 照合のテスト |

## 2. AI の扱い（判断させない・鵜呑みにしない）

| 番号 | 決まり | なぜ | 場所 | 確かめ方 |
|---|---|---|---|---|
| A-01 | AI の出力は下書き。保存されるのは、看護師が確定したもの（`POST /api/records`）だけ | 確定は人（テーマ "Own the Why"） | B | `test_A01_draft_alone_saves_nothing` |
| A-02 | AI が書くのは SOAP の S（患者の訴え）と O（観察・測定）だけ。A（アセスメント）と P（計画）は常に空で返し、AI の出力に入っていても捨てる | A・P は看護師の判断 | B | 下書きのテスト |
| A-03 | 下書きの全要素に根拠（発言番号、3つまで）を付ける。根拠がない・照合に通らないものは「止める」 | AI が補った部分を見つける | B | 照合のテスト |
| A-04 | 二段目の確認は、明示的に「根拠の発言から言える」と判定された文だけを通す。判定が返らない・失敗したときは「判断できない」で止める。**【11/8 強制】**二段目の結果にはサーバーが署名を付けて返し（`entail_seals`）、確定のときは署名で裏付けられた結果だけを使う。署名が合わない文（直した文、送られなかった文）は確定のときに二段目を呼び直す。画面から届いた判定はそのまま信じない | 黙って通さない | B | `test_A04_entail_no_verdicts_flags_all`・`test_A04_entail_partial_flags_missing_ones`・`test_A04_C06_entail_failure_flags_all`・`test_A04_sealed_results_are_not_judged_again`・`test_A04_edited_sentence_is_judged_again_at_confirm`・`test_A04_record_cannot_drop_entail_checks` |
| A-05 | 「止める」が付いた文は、看護師が1文ずつ「残す／消す」を決めるまで確定できない。二段目で付いた「止める」も、A-04 の署名の形でサーバーが確定のときに付け直すので、画面が外しても確定できない | 根拠のない文が気づかれずに記録に入るのを防ぐ | B（`409`）・F | `test_A05_record_blocked_until_stop_checks_decided`・`test_A05_stop_checks_must_be_decided` |
| A-06 | 【決定】「残す」を選んだ根拠のない文は、記録のデータに「看護師が確認して残した」と残す。カルテ用の文には印を出さない（カルテの書式を崩さないため） | 後から、AI が補った文を看護師が認めたと追える | B | `test_A06_kept_unsupported_sentence_is_marked_only_in_record` |
| A-07 | 薬の名前・量・回数は AI に書かせない。コードで見つけたら止め、「手で入力が必要」に回す | 聞き違いが重大な事故になる | B | 照合のテスト |
| A-08 | 依頼の緊急度は、会話の手がかり（患者が急ぎと言った／時間指定あり／なし）からコードが決める。AI は優先度を書かない（至急・優先などの語は止める）。看護師が変えたら「看護師が変えた」と残す | 優先順位を決めるのは人 | B・F（「AI の判断ではありません」と表示） | タスクのテスト |
| A-09 | 選んだ患者の情報を Gemini に渡さない | AI が選んだ患者を答えに写し、照合が意味を失うのを防ぐ | B | `test_A09_selected_patient_is_not_sent_to_gemini`・`test_A09_only_utterances_are_sent_to_gemini` |
| A-10 | 抜け（書くべきバイタルのうち無いもの）はコードで計算する。照合に通った値と、看護師の手入力の値だけを数える | AI の計算を鵜呑みにしない | B・F（確定前に計算し直す） | 照合のテスト |
| A-11 | 看護師が手で入れたバイタルは「手入力」として扱い、会話との照合をしない | モニターで見た値は会話に出ない | B | 照合のテスト |
| A-12 | 看護師が足した要素（依頼・S・O の文・医師への確認など、`added_by: nurse`）は AI 向けの照合と二段目にかけず、看護師が足したと記録に残す。根拠は任意で、付けるなら会話にある発言だけ。下書きにあった要素を看護師が足したと偽れないよう、`/api/drafts` が返す `draft_token`（AI の要素の指紋への署名）と照らし、下書きにあった文は AI の要素として扱う。token がない・合わないときは看護師が足した要素もすべて AI の要素として照合する | AI が拾い漏らした依頼を足せないと実際には使えない。一方で、照合を逃れる抜け道にしない | B | `test_A12_*` |
| A-13 | 依頼のラベル（中身の種類 `category`・誰が対応するか（職種）`role`）は AI が一覧から選んで付けるが、仕分けのためで優先度ではない（緊急度は A-08）。看護師が1タップで変えられ、変えたら看護師が変えたと残す（`category_set_by`・`role_set_by` を `nurse`）。一覧は仮置きで、コードの1か所（`app/models/labels.py`）にだけ書く | 依頼を誰が・何として片づけるかを一目で分けたい。AI の付けたラベルを優先度と取り違えないように | B | `test_A13_*` |

## 5. 費用と、止まらないこと

提出後（11/10 19:00〜11/14）は、再デプロイ・設定変更・手動の再起動や認証の更新がすべて禁止。**放っておいても動き続ける**ように作る。

|---|---|---|---|---|
| C-01 | Cloud Run は最大1インスタンス | 費用の上限を物理的に抑える | 設定 | 設定（デプロイ時の `--max-instances=1`。提出前に人が見る） |
